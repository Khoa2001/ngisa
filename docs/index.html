Tiếng Việt

Many agents. One repo. You merge.

NGISA (NGƯỜI GIÁM SÁT, "the supervisor") plans a task, hands the pieces to Claude Code workers, has every branch reviewed, and stops at a draft PR for you.

Try itSee the flow

Works with Flutter, Composer PHP and plain PHP repos.

Illustrative mock-up, not a recording.

What you get

  • ParallelUp to 3 workers per repo, each in its own git worktree, each on its own task.
  • GatedEvery worker runs the repo's own tool/setup.sh and must pass tool/ci_local.sh. A reviewer checks that the gate files were not touched. Flutter, Composer PHP and plain PHP repos get a gate generated for them.
  • YoursYou approve the plan. Workers cannot push. Only you merge to main.

From idea to merge

  1. Your ideaYou type a task to the NGISA.
  2. PlanNGISA writes a spec and a plan. You approve both.
  3. WorkersUp to 3, each in its own worktree, test first.
  4. Gatetool/ci_local.sh must exit 0.
  5. ReviewAPPROVE, or BLOCK back to the same worker. 2 rounds max.
  6. Your mergeDraft PR and CI. Only you merge to main.

Try it

  1. Install the scripts

    Once per machine: steps 1 to 3 of lab-quickstart.md.

  2. Make a lab copy and open the NGISA

    make-lab ~/Projects/<your-repo>
    repo-tab ~/lab/<your-repo>

  3. Give it a task

    Pick a small task with 2 independent parts, approve the plan, say go. Done? rm -rf ~/lab/<your-repo>.

Needs macOS, WezTerm, jq and a recent Claude Code (claude update), plus fvm for Flutter repos and composer for PHP repos.

Safety
  • The lab clone's push URL is DISABLED, and git push, pub publish, fastlane and firebase deploy are denied. The one way out is agent-pr, which refuses main, master, the base branch, worktree-* names and dirty trees, and which Claude asks you to approve on every call.
  • Nothing here touches ~/.claude or your real repo.
  • Do not run the NGISA or workers in bypass-permissions mode: agent reports to the NGISA then get held for approval. Use auto mode.
  • Max 3 agents per tab. All agents share one usage quota.

Experimental. Every run is logged under docs/runs/ as research data.
