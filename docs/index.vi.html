English

Nhiều agent. Một repo. Bạn merge.

NGISA (NGƯỜI GIÁM SÁT) lên plan cho task, giao từng phần cho các worker Claude Code, cho review mọi nhánh, rồi dừng ở draft PR để bạn quyết định.

Dùng thửXem luồng

Chạy được với repo Flutter, Composer PHP và PHP thuần.

Ảnh minh họa, không phải bản ghi thật.

Bạn được gì

  • Song songTối đa 3 worker mỗi repo, mỗi worker có git worktree riêng và một task riêng.
  • Có gateMỗi worker chạy tool/setup.sh của chính repo và phải qua tool/ci_local.sh. Reviewer kiểm tra file gate không bị sửa. Repo Flutter, Composer PHP và PHP thuần được tạo sẵn gate.
  • Của bạnBạn duyệt plan. Worker không push được. Chỉ bạn merge vào main.

Từ ý tưởng đến merge

  1. Ý tưởngBạn gõ task cho NGISA.
  2. PlanNGISA viết spec và plan. Bạn duyệt cả hai.
  3. WorkerTối đa 3, mỗi worker một worktree, viết test trước.
  4. Gatetool/ci_local.sh phải exit 0.
  5. ReviewAPPROVE, hoặc BLOCK quay lại đúng worker đó. Tối đa 2 vòng.
  6. Bạn mergeDraft PR và CI. Chỉ bạn merge vào main.

Dùng thử

  1. Cài các script

    Một lần cho mỗi máy: bước 1 đến 3 của lab-quickstart.md (tiếng Anh).

  2. Tạo bản lab và mở NGISA

    make-lab ~/Projects/<your-repo>
    repo-tab ~/lab/<your-repo>

  3. Giao việc

    Chọn một task nhỏ gồm 2 phần độc lập, duyệt plan, gõ go. Xong thì rm -rf ~/lab/<your-repo>.

Cần macOS, WezTerm, jq và Claude Code bản mới (claude update), thêm fvm cho repo Flutter và composer cho repo PHP.

An toàn
  • Push URL của bản lab là DISABLED, và git push, pub publish, fastlane, firebase deploy đều bị chặn. Đường ra duy nhất là agent-pr: nó từ chối main, master, nhánh gốc, tên worktree-* và cây làm việc chưa sạch, và Claude hỏi bạn duyệt ở mỗi lần gọi.
  • Không có gì ở đây đụng đến ~/.claude hay repo thật của bạn.
  • Đừng chạy NGISA hay worker ở chế độ bypass-permissions: báo cáo của agent gửi về NGISA sẽ bị giữ chờ duyệt. Dùng auto mode.
  • Tối đa 3 agent mỗi tab. Mọi agent dùng chung một hạn mức.

Thử nghiệm. Mỗi lần chạy được ghi trong docs/runs/ làm dữ liệu nghiên cứu.
