From idea to merge

NGISA · OpusImplementer · Sonnet, own worktreeReviewer · OpusYou decide
  1. Your ideaYou type a task to the NGISA.
  2. Brainstorm and specYou approve the spec.
  3. Plan and task splitFiles each task may touch. You approve the plan.
  4. agent-wall.shSpawns up to 3 workers and opens their panes.
  5. Implementersshelfie-cache, shelfie-sync, shelfie-ui: own worktree, TDD, tests green. Each reports to @NGISA.
  6. ReviewerAPPROVE or BLOCK. BLOCK goes back to the same agent, 2 rounds max. After 2 BLOCKs you break the tie.
  7. Feature branchci_local.sh and a draft PR.
  8. CI + Claude reviewOn GitHub / GitLab.
  9. Merge to mainOnly you, hook-enforced.

What only you do

  • SpecWhat you actually want
  • Plan and task splitA bad split means merge conflicts in every agent
  • Reviewer deadlockAfter 2 BLOCK rounds
  • Merge, release, publishBlocked by a hook for agents
  • Card / PII handlingRead it yourself, every time
  • Device feelCamera and scan UX, once per feature

Max plan limits

  • 3 per tab, 4 to 5 in totalagents per repo tab, and running at once across all repos.
  • About N times the burnwith N agents. They share the same 5-hour and weekly quota.
  • Sonnet for implementersOpus only for the NGISA and the reviewer.

Full setup, with the agent files, the agent-wall.sh script and the hook rules, is in one-terminal-orchestrator.md.
